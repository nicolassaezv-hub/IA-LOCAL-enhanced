FASE 5
Prediction Lab
Sistema Inteligente de Desarrollo de Sistemas Predictivos
Complejidad Alta 8 archivos 5–7 sesiones
▼
Flujo completo
Descripción natural→ Dataset adjunto→ Prompt Analyzer→ Dataset Analyzer→ Feasibility Engine→ Model Planner→ Pipeline Generator→ Validation Engine→ Report Generator
5.1
Prompt Analyzer
prediction_lab/prompt_analyzer.py
Interpreta la idea del usuario en lenguaje natural. Extrae tipo de problema, variable objetivo, features candidatas, horizonte temporal y tipo de salida esperada. Devuelve un objeto ProblemSpec estructurado.
lab analiza "<idea>"
5.2
Dataset Analyzer
prediction_lab/dataset_analyzer.py
Analiza el dataset en profundidad: filas, columnas, % NaN, balance de target, correlaciones Pearson + VIF, outliers IQR/z-score, skewness, kurtosis. Puntúa la calidad 0–100 por dimensión.
lab dataset <archivo.csv>
5.3
Feasibility Engine ⭐
prediction_lab/feasibility_engine.py
Componente central. Responde: "¿puede construirse un predictor útil con esto?" Calcula un Índice de Viabilidad 0–100 ponderando cantidad de datos (25%), calidad (20%), balance (15%), señal predictiva (20%), complejidad (10%), horizonte (10%). Si viabilidad < 40% → explica qué falta y no procede.
lab viabilidad <csv> "<idea>"
5.4
Model Planner
prediction_lab/model_planner.py
Selecciona automáticamente qué modelos entrenar según el tipo de problema detectado. XGBoost, LightGBM, RF, Logistic Reg. para clasificación; Regresores para regresión; ARIMA/LSTM para series temporales. Justifica técnicamente cada decisión.
lab modelos <csv> "<idea>"
5.5
Pipeline Generator
prediction_lab/pipeline_generator.py
Genera la carpeta completa del proyecto: dataset_loader.py, feature_engineering.py, train.py, predict.py, evaluate.py, visualization.py, report.py, config.json, README.md. Todo adaptado al dataset concreto con nombres de columnas reales.
lab generar <csv> "<idea>" [nombre]
5.6
Validation Engine
prediction_lab/validation_engine.py
Entrena y compara todos los modelos candidatos con CV-5 estratificada. Métricas según tipo: F1/AUC/Brier para clasificación, MAE/RMSE/R² para regresión. Selecciona el mejor con justificación + importancia de variables (SHAP).
lab entrenar <proyecto>lab comparar <proyecto>
5.7
Report Generator
prediction_lab/report_generator.py
Genera informe técnico completo en Markdown: viabilidad, modelos evaluados, mejor modelo, métricas, variables clave, riesgos identificados, mejoras sugeridas, lista de archivos generados.
lab reporte <proyecto>lab proyectos
FASE 6
Feedback System
Sistema de Retroalimentación Evolutiva
Complejidad Media 7 archivos 3–4 sesiones
▼
6.1
Tool Tracker
feedback/tool_tracker.py
Instrumenta todas las herramientas via decorator @track_tool. Registra tiempo de ejecución, resultado (éxito/fallo/error), tipo de excepción, CPU/RAM delta y frecuencia de uso por herramienta.
6.2
Model Tracker
feedback/model_tracker.py
Historial de rendimiento de todos los modelos (Accuracy, F1, AUC por par/proyecto). Detecta model drift si la precisión cae >5% vs. el mejor registro histórico y lanza alerta automática.
feedback modelo EURUSDfeedback drift
6.3
System Tracker
feedback/system_tracker.py
Monitorea CPU, RAM, GPU, espacio en disco y tiempos de respuesta del LLM durante cada ejecución. Alerta si CPU >85% o RAM >80% en entrenamientos.
6.4
User Feedback Collector
feedback/user_feedback.py
Captura señales explícitas (feedback bueno/malo) e implícitas (detecta "error", "mal", "perfecto", "funciona" en el texto del usuario). Asocia cada señal al último comando ejecutado.
feedback buenofeedback malofeedback "<texto>"
6.5
Feedback Aggregator
feedback/feedback_aggregator.py
Consolida todas las fuentes en un informe interno por sesión: tasa de éxito de herramientas, modelo con mejor/peor rendimiento, alertas de drift, feedback del usuario, picos de recursos.
feedback reportefeedback historia
6.6
Evolution Memory
feedback/evolution_memory.py
Persiste el conocimiento acumulado en evolution.db (SQLite separada). Tablas: session_reports, model_history, tool_stats, user_preferences. Base de datos que alimenta el Evolution Engine.
feedback tendencias
FASE 7
Evolution Engine
Motor de Mejora Continua — ASTRA analiza y mejora su propio código
Complejidad Alta 5 archivos 4–5 sesiones
▼
7.1
Supervisor
evolution/supervisor.py
Thread daemon siempre activo. Solo observa: rendimiento de herramientas, calidad de modelos vs. historial, frecuencia de errores, consumo de recursos. Genera snapshots de estado cada N horas en evolution.db. Nunca modifica nada.
evolution statusevolution snapshot
7.2
Repair Engine
evolution/repair_engine.py
Analiza errores recurrentes del Feedback System. Para cada error: localiza el archivo y función, diagnostica la causa probable, propone un parche con código concreto, explica el motivo técnico y estima el riesgo (bajo/medio/alto). Nunca aplica cambios.
evolution erroresevolution parche <id>
7.3
Innovation Engine
evolution/innovation_engine.py
Detecta oportunidades de mejora: código duplicado, módulos redundantes, cuellos de botella (del Tool Tracker), patrones de uso que podrían automatizarse, nuevas ramas cuando funciones relacionadas alcanzan masa crítica. Ordena por prioridad = Impacto / Esfuerzo.
evolution oportunidadesevolution innovacion
7.4
Proposal Store
evolution/proposal_store.py
Base de datos de propuestas generadas por Repair e Innovation. Almacena: descripción, archivos afectados, código propuesto, riesgo, impacto, estado (pendiente/aprobada/rechazada/aplicada) e historial de decisiones del desarrollador.
evolution propuestasevolution aprobar <id>evolution rechazar <id>
FASE 8
Constitution Engine
Motor de Seguridad y Gobernanza — ASTRA nunca se rompe a sí misma
Complejidad Media 6 archivos 3–4 sesiones
▼
8.1
Validator
constitution/validator.py
Verifica automáticamente cada propuesta: compatibilidad de imports, dependencias rotas, impacto en módulos, integridad del Core (main.py, memory.py, ai_models.py), sintaxis via ast.parse(), existencia de tests, posibilidad de rollback.
8.2
Reglas Fundamentales
constitution/rules.py
8 reglas inmutables: nunca modificar Core automáticamente, nunca eliminar módulos sin aprobación, todo cambio tiene snapshot previo, todo cambio queda registrado, respaldo de tests obligatorio, no eliminar comandos CLI, no modificar schema de memoria.db sin migración, arquitectura modular inviolable.
constitution reglas
8.3
Rollback Manager
constitution/rollback_manager.py
Antes de aplicar cualquier cambio: snapshot comprimido de archivos afectados, registro en rollback_log. Si la aplicación falla → restauración automática. Mantiene los últimos 10 snapshots con rotación.
constitution snapshotsconstitution rollback <id>
8.4
Approval Flow
constitution/approval_flow.py
Flujo completo: propuesta entra → Validator verifica → si pasa: presentar al desarrollador con resumen + archivos + riesgo + código + test sugerido → desarrollador aprueba/rechaza → si aprobado: snapshot + aplicar + Audit Log.
constitution aprobar <id>constitution rechazar <id>
8.5
Audit Log
constitution/audit_log.py
Registro inmutable de todos los cambios aplicados: timestamp exacto, archivos y líneas modificadas, justificación de la propuesta, aprobación del desarrollador, resultado (éxito/fallo/rollback).
constitution auditoriaconstitution auditoria <fecha>

ASTRA ejecuta→ Tool + System Tracker→ Feedback Aggregator→ Supervisor detecta→ Repair / Innovation→ Constitution valida→ Tú apruebas→ Snapshot + aplica→ Evolution Memory aprende
